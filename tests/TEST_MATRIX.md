# KariDNS Test Suite Matrix & RFC Traceability Document

This document provides a comprehensive traceability matrix mapping every test in the KariDNS test suite (243 test targets registered in `tests/run_all_suite.sh` — C unit test binaries, integration shell scripts, sanitizer tests and fuzzing harnesses — plus the targets listed in §3.13) to its corresponding **IETF RFC / Technical Specification**, target **KariDNS Component**, and **Test Classification** (Positive, Negative, Boundary, Concurrency/RCU, Memory/ASan, Fuzzing).

It directly cross-references the implementation status documented in [`KariDNS_RFC_GUIDELINE.md`](../KariDNS_RFC_GUIDELINE.md).

---

## 1. Test Suite Architecture & Organization

The KariDNS automated test suite is managed via the unified runner script [`tests/run_all_suite.sh`](run_all_suite.sh) and the project [`Makefile`](../Makefile).

[`tests/run_dag_ci_test.sh`](run_dag_ci_test.sh) is the umbrella runner for the dag CLI checks (Part 1-19 plus the Part 20-21 parallel sub-suites); the other dag test scripts are registered individually in `run_all_suite.sh`.

### 1.1 Test Category Distribution in `run_all_suite.sh`

| Category Code | Category Name | Target Domain | Registered Tests | Primary Execution Method |
|:---|:---|:---|:---:|:---|

## 4. Execution & Coverage Measurement Guide

### 4.1 Running Tests

```bash
# 1. Run full test suite with formatted summary report
sh tests/run_all_suite.sh

# 2. Run specific category
sh tests/run_all_suite.sh --category unit
sh tests/run_all_suite.sh --category xfr,dnssec,update

# 3. Filter by test name
sh tests/run_all_suite.sh --filter axfr

# 4. Skip tests whose name contains any of the given substrings
sh tests/run_all_suite.sh --exclude run_stress_test,run_fuzz_smoke_test

# 5. Quick mode (fast unit and core tests only)
sh tests/run_all_suite.sh --quick

# 6. Skip the dag category
sh tests/run_all_suite.sh --no-dag

# 7. Stop immediately on first failure / print test output in real time
sh tests/run_all_suite.sh --stop-on-failure
sh tests/run_all_suite.sh --verbose

# 8. Number of tests running at the same time (default: $KARI_JOBS, else the CPU count)
sh tests/run_all_suite.sh -j 4
sh tests/run_all_suite.sh -j 1       # one test at a time, registration order

# 8. List all registered tests
sh tests/run_all_suite.sh --list
```

Integration tests that need loopback aliases (127.0.0.2 and up) add them when run as root and report SKIP otherwise.

### 4.1.1 Parallel execution (`-j`)

`run_all_suite.sh` runs `N` tests at a time (`-j N`, `--jobs N`; default `$KARI_JOBS`, else `sysctl -n hw.ncpu`, `nproc`, 1). `-j 1` is the old sequential run: registration order, the by-name cleanup before every test. `--verbose` implies `-j 1`; at most 29 jobs.

- **Slots.** Test `i` of a batch runs in a slot `s` (0 .. N-1) and gets `KARI_SLOT=s`, `KARI_PORT_BASE=20000 + 1000*s` and `KARI_TMP=<scratch>/s<s>` (an empty directory, emptied before and after every test). A script takes its ports with `kari_port <offset> [fallback]` from [`tests/lib_proc.sh`](lib_proc.sh): `KARI_PORT_BASE + offset` under the runner, `fallback` (the port or PID formula it used before) when run on its own, so every script still runs standalone as `sh tests/run_X_test.sh`. A script keeps its offsets below 1000 and different per port (neighbour ports such as `PORT + 1` stay derived from one `kari_port` call; the scripts that need more than one start them 100 apart). Temporary files are made with `mktemp -d` (or a `$$`-suffixed name), never a shared fixed path.
- **Own session.** Each test runs in a session of its own (`perl -MPOSIX -e 'POSIX::setsid(); exec @ARGV'`); when it ends the runner kills that process group and nothing else. The by-name cleanup (`cleanup_stale_processes`: `pkill -f mock_*.pl`, `/tmp/karidns*.sock`, `tests/*.tmp`) runs only while no test is running: at the start, at the end and around each serial test.
- **Order.** The parallel tests start longest first, by the times in the previous `tests/.test_logs/summary.tsv` (tests it does not list count as 10 s; no previous file: registration order). One line per test is printed when it finishes, a FAIL with the tail of its log. `summary.tsv` and the final report are in registration order. `--stop-on-failure` kills the running tests and stops.
- **Exclusive groups and serial tests.** `register_test <category> <bin|sh> <command> <description> [par|group:NAME|serial]`.
  - `group:NAME` (several: `group:a+b`): the tests of one group run one at a time, but next to the `par` tests (a group occupies one slot while it runs); a free slot takes the first not yet started test of the longest-first queue whose groups are idle. Groups: `alias` (tests that add loopback aliases 127.0.0.2 and up with `ifconfig lo0 ... alias`; checked on FreeBSD 15.1: 240 add/remove cycles, `/32` and `/8` form, did not disturb connections to 127.0.0.1), `pg` (one PostgreSQL server: roles and databases).
  - `serial`: runs alone, one by one, after the batch: stress, performance, sanitizer, fuzz and TSan jobs, `run_dag_ci_test.sh` (about 35 sub-tests of its own), tests that edit `tests/zones/example.com.zone` (read by other tests), tests with fixed ports or files in `/tmp` (`run_notify_source_test.sh`: ports 10053/10054 and the loopback alias 127.0.0.2).
  - The reason is the comment on the `register_test` line. When you cannot make a new test independent of the others, give it a group or `serial`.
- **Rules for a new test.** Always give a test that starts karidns with a `control-channel` a control socket of its own, `socket "$TMP_DIR/ctl.sock";`, in a directory of the test (owned by root or by the caller, not writable by others; not `/tmp` itself), and the same `socket` in its `karictl.conf`: without `socket` the server binds `/var/run/karidns/control.sock` and unlinks and re-binds that path, so a test running next to it takes it over and its `karictl reload` / `reconfig` reaches the wrong server (the result looks like a flaky reload). `control-channel { }` has no `port` or `bind-address` (an unknown key is a configuration error); `kari_test_conf` and `kari_ctl_conf` in `tests/lib_proc.sh` make a copy of `tests/karidns-test.conf` / `tests/karictl-test.conf` with the test's port and socket. Take every port from `kari_port`; put every file under `mktemp -d` (or `${KARI_TMP:-...}`); stop the servers you started with `kari_kill_tree "$PID"` or `kari_kill_conf <your conf>`, never `killall` or an unscoped `pkill`; do not add or remove loopback aliases unless the test is in group `alias`; a script that starts other `kari_port` scripts at the same time must give them separate windows (`run_dag_ci_test.sh` unsets `KARI_PORT_BASE` for its sub-tests).
- **Coverage.** `make coverage-run` passes `-j $(COV_JOBS)` (`make coverage COV_JOBS=1` for the sequential run). Profile files are per process (`%p`, classic mode) or per instrumented binary and shared with `mmap` (`%m`, `%c`, continuous mode), both safe for concurrent processes.


Tests stop only the servers they started, so other karidns instances on the host (another working copy, a long-running server) survive a suite run. Test scripts source [`tests/lib_proc.sh`](lib_proc.sh) and use `kari_kill_tree "$SERVER_PID"` (the karidns supervisor and its backend/router/broker children) or `kari_kill_conf <test-specific config path>`; do not use `killall` or an unscoped `pkill`/`pgrep`. `run_all_suite.sh` stops only the karidns servers that carry its own `KARIDNS_SUITE_ID` in their environment (and, per test, the process group of that test).

Unit test binaries can also be built and run from the Makefile: `make unit-tests` (all), `make <name>_test` (one), and `make unit-tests-asan` / `make test_<name>-asan` for ASan/UBSan builds.

### 4.2 Measuring Code Coverage with Clang

KariDNS supports Clang source-based code coverage (`-fprofile-instr-generate -fcoverage-mapping`):

```bash
# Clean, instrument build, execute test suite, and generate HTML report
make coverage

# Individual coverage steps:
make coverage-clean   # Remove previous raw and HTML coverage files
make coverage-build   # Compile all targets with instrumentation
make coverage-run     # Run tests/run_all_suite.sh (excluding COV_SUITE_EXCLUDE) and the fuzz corpora with LLVM_PROFILE_FILE
make coverage-report  # Merge .profraw files, generate coverage_html/ and run tests/coverage_gate.pl
```

HTML coverage reports with line and branch-level precision will be written to `coverage_html/index.html`. `coverage-run` needs root for the integration tests that use loopback aliases. The CI job "Coverage gate" checks the per-tier thresholds with `perl tests/coverage_gate.pl --phase=2 --strict`; the latest measured values are in [`docs/COVERAGE_STATUS.md`](../docs/COVERAGE_STATUS.md).
